# GraphQL Shield — Setup & Reproduction Guide

This document lets an external reviewer go from a bare checkout to a running
gateway and a passing test suite without guesswork. The project is dependency-light:
the core application needs only FastAPI, Uvicorn, Strawberry GraphQL, graphql-core,
PyJWT, and pydantic-settings.

---

## 1. Prerequisites

| Requirement | Version |
|---|---|
| Python | 3.11 or newer (validated on 3.14.5) |
| pip | bundled with Python |
| Git | any recent version |

No Node.js, database server, or external API key is required to run the core
application or its test suite. (Node.js is only needed if you choose to
regenerate the DOCX/PPTX deliverables — see §6.)

---

## 2. One-command bootstrap (recommended)

From the repository root:

**Windows (PowerShell 5.1+):**
```powershell
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
```

**Linux / macOS / Git Bash / WSL:**
```bash
bash scripts/bootstrap.sh
```

The script performs, in order:

1. Creates a local virtual environment in `.venv/`
2. Upgrades pip
3. Installs dependencies from `requirements.txt` **constrained** by `constraints.txt`
4. Copies `.env.example` → `.env` if `.env` is absent
5. Seeds the SQLite database (`python -m app.seed`)
6. Runs the full test suite (`python -m pytest tests/ -q`)

A successful run ends with `299 passed` and prints the server start command.

## 3. Manual setup

```bash
python -m venv .venv

# Windows:        .venv\Scripts\Activate.ps1
# Linux/macOS:    source .venv/bin/activate

pip install --upgrade pip
pip install -r requirements.txt -c constraints.txt
cp .env.example .env          # first time only
python -m app.seed
python scripts/verify_audit_remediation.py   # 15 automated checks (<7s)
python -m pytest tests/ -q                   # 299 passed (~60s)
```

### Why `constraints.txt`?

`requirements.txt` intentionally lists broad, compatible version ranges so the
project is not artificially locked to one Python release. `constraints.txt`
pins the **exact** versions that were installed and validated (299 tests passing)
and is applied with `-c` so that a reviewer reproduces the same dependency graph:

```bash
pip install -r requirements.txt -c constraints.txt
```

Pins were verified for mutual compatibility, not chosen blindly. If you cannot
use the pinned set, plain `pip install -r requirements.txt` still works.

## 5. Reproducing the evaluation

All evaluation artifacts are deterministic and offline (no LLM credentials needed
for the core benchmark):

```bash
# 0. Automated remediation verification (<7s)
python scripts/verify_audit_remediation.py

# 0b. Full test suite (299 passed in ~60s)
python -m pytest tests/ -q

# 1. Build the 115-case ground-truth corpus
python scripts/build_ground_truth_corpus.py

# 2. Multi-method benchmark -> docs/EVALUATION_REPORT.json
python scripts/evaluate_taint_corpus.py --corpus data/ground_truth_corpus.json \
    --output docs/EVALUATION_REPORT.json

# 3. Phase 7 comparative evaluation -> docs/PHASE_7_RESULTS.json
python scripts/evaluate_phase_7.py --corpus data/ground_truth_corpus.json \
    --output docs/PHASE_7_RESULTS.json

# 4. Security performance overhead
python -m scripts.evaluate_performance

# 5. Anomaly-detection evaluation
python scripts/evaluate_anomaly.py
```

Canonical, machine-readable metrics are consolidated in
`docs/RESULTS_SUMMARY.json`. Real captured command transcripts live in
`docs/evidence/`.

## 6. Regenerating the DOCX/PPTX deliverables (optional)

The office documents are generated by Node scripts under `tools/report/`
(dev-only tooling; excluded from the runtime dependency set):

```bash
cd tools/report
npm install                 # installs docx + pptxgenjs
node make_report.js         # -> CCNS_Project_Report.docx
node make_pptx.js           # -> CCNS_Presentation.pptx
node make_viva.js           # -> VIVA_QA.docx
```

These are optional: the generated `.docx`/`.pptx` files are already committed.

---

## 7. Packaging a clean submission archive

```bash
python scripts/package_submission.py
```

Builds `GraphQLShield_Submission.zip` from an explicit whitelist (source, tests,
scripts, docs, data, deliverables) and writes `MANIFEST.sha256`. It deliberately
excludes `.git/`, `__pycache__/`, `.pytest_cache/`, `.venv/`, `*.pyc`, `*.db`,
`.env`, and any nested archives.

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: graphql` | `graphql-core` missing (older `requirements.txt`) | `pip install -r requirements.txt -c constraints.txt` |
| `ModuleNotFoundError: strawberry` | dependencies not installed | run the bootstrap script |
| Tests error on `pytest.mark.asyncio` | `pytest-asyncio` missing | install from `requirements.txt` |
| Emoji `UnicodeEncodeError` in demo scripts on Windows | cp1252 console | scripts already force UTF-8; or `set PYTHONUTF8=1` |
| Port 8000 in use | another process bound | `uvicorn app.main:app --port 8001` |
